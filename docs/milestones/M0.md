## 2. Address plan and host

`make doctor` does not change the host. It reads ranges from the four sources below and checks whether they overlap the five ranges of the address plan.

| Source | Command |
|---|---|
| Interface addresses | `ip -j addr show` |
| All routing tables, IPv4 and IPv6 | `ip -j route show table all` |
| docker networks | `docker network ls -q`, `docker network inspect` |
| libvirt networks | `virsh -c qemu:///system net-list --all`, `net-dumpxml` |

The IPv4 ranges doctor found on its own on this host include `172.16.0.0/24`, the docker bridges `172.17.0.0/16` through `172.24.0.0/16`, libvirt `192.168.122.0/24`, Cilium `10.42.0.0/24`, and Tailscale `/32` addresses and routes inside `100.64.0.0/10`. Docker bridges whose link is down are included. The lab address plan overlaps none of them.

When the plan is changed to overlap `docker0` (`rdma: 172.17.0.0/24`), doctor prints a separate `[fail]` for the overlap with the address, the connected route, the local route and the docker network, and exits with code 1. It also prints the plan contradiction that the node RDMA addresses lie outside the new RDMA network.

## 4. RXE prerequisite probe

Before building M1, the three most uncertain points were checked in real guests. The logs are `docs/milestones/evidence/m1/probe.log` and `probe-fault.txt`. The originals are in `.lab/probe/20261115T012426Z/`.

| Question | Observation |
|---|---|
| Does the guest kernel have `rdma_rxe`? | Not 6.8.0-147-generic of the 20261017 image. `linux-modules-extra-6.8.0-147-generic` (noble-updates, noble-security) provides `rdma_rxe.ko.zst` |
| Does the second NIC carry frames between the two guests without leaving the host? | `-netdev dgram` was connected over two AF_UNIX sockets. ping 3/3, and the neighbor entry holds the peer lab NIC MAC `52:54:00:4d:00:12` |
| Does `rdma link add` attach to that NIC, and does `rping` complete? | `rxe0` attached to `enp0s4` as ACTIVE. `rping -C 5 -V` ended with exit code 0 on both sides |

All three answers were "yes", so M1 went ahead.
