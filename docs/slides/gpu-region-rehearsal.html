Open with the cost: a GPU region is built from hundreds of facts that people agree on before any hardware works, and a wrong one is found on site. This talk rehearses those facts on one Linux host. Speaker notes · 1:00–2:40 (1:40)

Three kinds of facts. The address plan: 13 hosts with 95 addresses in 21 ranges, counting the pod ranges of every rail. The cabling: in a rail-optimized fabric, rail r of every node goes to the leaf of rail r, and one swapped cable breaks that silently. The cluster: what each node class gets installed.

These facts live in spreadsheets, a DCIM, an inventory and Helm values. The talk keeps them in one file and checks them before anything is built.

cel1: an invented region with a real shape

02 / THE REGION
restack / rdma-fabric-lab
03 / 14
cel1: an invented region with a real shape
8 eight-rail GPU nodes, 8 rail leaves and 4 spines, joined by 128 cables.
Speaker notes · 2:40–4:30 (1:50)

The compute fabric is rail-optimized: one leaf per rail, 8 downlinks and 8 uplinks on each leaf, so no leaf is oversubscribed. 64 rail cables and 64 leaf to spine cables, 128 in an explicit list. No rule generates them, so the validator checks the cabling plan as written.

There are 8 DGX nodes, not 64, because one host cannot simulate more. The shape is what matters for the checks. The 3 control planes and the 2 PCIe GPU nodes have no fabric cable.

The validator rejects invalid plans

04 / VALIDATE
restack / rdma-fabric-lab
05 / 14
The validator rejects invalid plans
PyYAML, Ansible and NetBox would take each of these without a word.
A rail port cabled to the leaf of another rail.
Two ranges that overlap, or an address outside its network.
A port used twice, or a rail port without a cable.
A pod range too small for the nodes it must serve.
A key written twice in the YAML file.
One unit test per violation. Each fails if the validator misses it.
Speaker notes · 6:20–8:20 (2:00)

The validator reports each violation by name. The examples on the slide are real rules: a rail cabled to the wrong leaf, overlapping ranges, a port used twice, a rail pod range that does not fit its nodes in blocks, and a key that appears twice in the file, which PyYAML would silently resolve to the later value.

Each rule has a unit test that fails if the validator misses the violation. That is the same habit the scenarios follow later: a check counts only after it has failed once.

Speaker notes · 8:20–10:30 (2:10)

The ibsim topology is rendered from the cable list of the model. OpenSM, the real subnet manager, discovers it, assigns 76 LIDs and routes it with updn. The scenario then removes one leaf to spine link. 13 routes left through the two ports of that link, all 13 moved to other ports, every LID still answered, and the recovery restored the baseline.

This is the management plane only. It shows that the cabling plan gives the subnet manager a fabric it can route, and that a link failure is survivable on paper.

Speaker notes · 16:40–18:30 (1:50)

A rehearsal is only worth its checks. Every check of every scenario must fail on at least one deliberate break and pass after the repair. A break changes one thing, and the run must end failed with the named checks failed, not with any nonzero exit.

The break scripts of the Kubernetes RDMA scenarios, the rail networks and NetBox hold 20, 7 and 8 breaks. A break run is marked in its manifest, so the report of the latest results leaves it out.

What the rehearsal caught

10 / FINDINGS
restack / rdma-fabric-lab
11 / 14
What the rehearsal caught
Each was found on guests, before any hardware was involved.
A pod created at boot started without its second network, and no error.
A restarted Cilium agent could not reach the API through the ClusterIP.
The RDMA device plugin finds devices only on PCI functions.
Its DaemonSet schedules nowhere without NFD’s Mellanox label.
The Whereabouts daemon ignores SIGTERM, so each reboot waits 90 s.
Speaker notes · 18:30–20:40 (2:10)

Five findings, each with its evidence in the repository. With the primary CNI’s file in the directory containerd reads, a pod created right after a boot ran with eth0 only, so the lab moved that file. A restarted Cilium agent lost the API when the default route sat on another NIC, so the agent now uses the API address itself.

The device plugin reads RDMA devices from PCI functions, so Soft-RoCE cannot stand in for an HCA. Its DaemonSet needs the NFD label of a Mellanox PCI device. The Whereabouts daemon container does not stop on SIGTERM, and systemd kills it after 90 s at every reboot.

What only hardware can show

11 / LIMITS
restack / rdma-fabric-lab
12 / 14
What only hardware can show
The simulation rails carry Ethernet. Nothing here is an InfiniBand data path.
IPoIB interfaces in pods, and traffic on the rails.
An RDMA device in a pod through the device plugin.
The real NVIDIA container toolkit and GPU Operator operands.
NDR links, firmware and any performance number.
Each stays not_run in the repository until a run on hardware exists.
Speaker notes · 20:40–22:20 (1:40)

Be exact about the boundary. IPoIB attaches only to a port whose link layer is InfiniBand, and no guest has one. The device plugin exposes no device without a PCI function. There is no GPU, so the operator creates no operand. Nothing in the talk is a throughput or latency result.

The repository lists these items as not_run with the reason for each, and the result kinds keep a simulation from being read as a hardware measurement.
