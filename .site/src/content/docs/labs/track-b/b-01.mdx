The smallest fabric that needs a subnet manager is two HCAs on one switch. B-01 runs OpenSM against that fabric in ibsim and checks, with the standard diagnostic tools, everything the SM is supposed to have done: discovery, LIDs, port states, forwarding tables, and reachability by LID.

## Goal

Show that OpenSM reaches SUBNET UP on the B-01 fabric, that `ibnetdiscover` finds exactly the nodes and links of the net file, that every linked port is Active with a unique non-zero LID, and that the switch forwards every endpoint LID correctly.

## Concepts it uses

- [The subnet manager and its sweep](/concepts/infiniband-management/).
- [GUIDs, LIDs and port states](/concepts/infiniband-management/).
- [ibsim and libumad2sim](/concepts/infiniband-management/), the stand-in for hardware.

## Run it

```bash
make track-b                         # boots ibsim1, prepares it, builds the image, runs B-01 to B-04
make track-b-breaks                  # each scenario must end failed on its deliberate break
make lab-down LAB_PROFILE=ibsim
```

`make track-b` runs `python -m ibsim run --scenario <name>` for each scenario under one run id. The runner on the host reaches the guest over SSH and never starts a simulator, a tool or a container itself. Inside the guest, `tracks/b-ibsim/scripts/guest.sh start` starts one container per run. OpenSM runs with `-R minhop`, attached at `hca1`.

## What every check proves

<ScenarioChecks spec="b-ibsim/b-01" />

`topology-discovered` compares against the net file, not against a list typed into the test, so a fabric change cannot pass by accident. `lid-reachability` sends a LID-routed `smpquery nodedesc` to every LID, which works only after the SM wrote the forwarding tables. `host-untouched` scans the host at the start and the end of the run for any simulator process or Track B container.

## Break it yourself

`python -m ibsim run --break` removes one link from the net file the simulator gets, while every expectation still comes from the full topology file. For B-01 the removed link is `"hca2"[1]-"sw1"[2]`.

```bash
make track-b-breaks
```

<Excerpt id="b01-break" />

`routes-shortest` still passed, which is correct. With `hca2` gone, the switch still forwards the one remaining endpoint LID out of the right port. All four break runs of `20261115T151828Z` failed with class `assertion-failed`, and `rfl validate` accepted them ([ADR 0005](/docs/adr/0005-track-b-fabric-simulation/) section 3).

## Questions to think about

- The SM attaches at `hca1`. How does it reach `hca2` before any forwarding table exists?
- Why would a LID of 0 on an Active port be a failure, and what does LMC 0 promise about the number of LIDs per port?
- The six unlinked ports of `sw1` show `Down/Polling`. Why does `port-states` check them at all?

## What the result means and does not mean

The run shows OpenSM discovering, addressing and routing a two-HCA fabric correctly as ibsim presents it, with the standard tools reading the result.

> [!WARNING]
> This is a management simulation. It shows no hardware, firmware, link timing, IPoIB or RDMA data path. MADs travel over ibsim's Unix socket through libumad2sim, and ibsim reports every link as 4X SDR at 2.5 Gbps.
