The simplest way to give a container RDMA is to let it use the node's own device. This scenario starts one pod per worker with `hostNetwork: true`, runs the pinned RDMA test image in it, and repeats [vm-rxe-baseline](/labs/track-a/vm-rxe-baseline/) unchanged between the pods, against the lab NIC addresses.

## Goal

Show that a container on each worker can open the node's `rxe0` and complete rping and RDMA Read, Write and Send, with the frames on the lab NIC only, and record exactly which pod security profile that needs and that every narrower profile fails.

## Concepts it uses

- [hostNetwork pods with RDMA devices](/concepts/kubernetes-networking/), the device cgroup and Pod Security Standards.
- [Memory regions and memlock](/concepts/rdma/), which the pods' limits must allow.
- Every concept of [vm-rxe-baseline](/labs/track-a/vm-rxe-baseline/), whose checks run inside the pods.

## Before you start

| Item | Value |
|---|---|
| Profile | `lab`: `cp1` 2 vCPU, 4 GiB, and `worker1`, `worker2` 4 vCPU, 6 GiB each. Only these three ran during the runs of record |
| Cluster | `make k8s` and `make addons ENV=lab` done, Cilium, Multus and Whereabouts installed |
| Image | `docker.io/library/rfl-rdma-tools:m3@sha256:756e51cf…`, built in the Track B guest with `make rdma-tools-image` and imported with `make rdma-tools-load` |
| Version lock | `make versions SCOPE=m3` must return 0 |

**Time taken.** <Duration id="a-hostnet-time" />. Each perftest test is one burst of about 16 ms.

## Run it

```bash
make rdma-tools-image               # builds inside the Track B guest, never on the host
make lab-down LAB_PROFILE=ibsim     # stop the builder before measuring
make rdma-tools-load                # ctr import on both workers, by digest, no registry
make k8s-hostnet-test               # this scenario
```

The pods sleep, and the runner starts every process through `kubectl exec` on `cp1`, under `timeout`. The image is referenced by digest with `imagePullPolicy: Never`. `ctr import --digests` names it by the sha256 of `index.json`, and CRI resolves a pod's `name@digest` only by that name, so the lock pins the index digest ([M3](/docs/milestones/m3/) section 2).

## The narrowest profile that works

| # | Profile | Result |
|---|---|---|
| 1 | Namespace at PodSecurity `restricted` | Refused at admission for `hostNetwork=true` |
| 2 | Namespace at PodSecurity `baseline` | Refused at admission for `hostNetwork=true` |
| 3 | `privileged` level, uid 65534, all capabilities dropped, no privilege escalation, `RuntimeDefault` seccomp, no device | No `/dev/infiniband`. `ibv_devinfo` exits 255 with `No IB devices found` |
| 4 | Profile 3 with `/dev/infiniband` as a hostPath | The files appear with mode 0666, but opening `uverbs0` and `rdma_cm` gives `Operation not permitted` |
| 5 | `privileged: true`, uid and gid 65534, no host PID or IPC, no volume, no runtime socket | `rxe0` is `PORT_ACTIVE`, no effective capability, and `ib_write_bw` completes between the pods |

The user accepted `privileged` for the lab RDMA pods on 2026-11-16. The pods run with 8388608 bytes of memlock, containerd's default, and the tests need less than 64 KiB ([M3](/docs/milestones/m3/) section 5).

## Questions to think about

- Profile 4 shows the device files with mode 0666, yet opening them fails. Which kernel mechanism decides, and why does dropping or adding capabilities not change it?
- The pods share the node's network namespace and the whole RDMA device. What could one pod do to another pod's RDMA traffic on the same node?
- With `LimitMEMLOCK=65536`, rping and the perftest tests still passed. What does that tell you about the size of the registrations these tests make?
- The pod bandwidth figures fall inside the spread of the VM runs. Why does that not show that a container costs nothing?

## What the result means and does not mean

The run shows that a container on a worker can open the node's RXE device and run RDMA CM, Read, Write and Send against the lab NIC addresses, with the frames on the lab NIC only.

> [!WARNING]
> It does not show a pod-private interface, device isolation between pods, Cilium's pod data path, or any way to run RDMA without `privileged`. Bandwidth is a software measurement of this host and guest pair, one 16 ms burst per figure, with no pass threshold.
